## 1. デザインの核

コンセプト案：**「歌が灯る、小倉の喫茶。」**

実際の外観にある紫色の看板、店内の青紫のステージ照明、白いソファ、木のテーブルを視覚的な起点にする。歌う場所としての華やかさと、食事も楽しめる喫茶の親しみやすさを一つのページで伝える。

訪問者が「雰囲気を見る → お店での過ごし方を知る → 食事と利用案内を見る → 電話・地図で行動する」の順に理解できる構成にする。

| --- | --- | --- |
| 主背景 | 温かみのある生成り `#F4EDE2` | 白いソファと喫茶の柔らかさ |

大きな角丸カードを各セクションに反復しない。店内は大きな写真、料理は喫茶メニューを思わせる組版、料金は比較表、アクセスは実用情報というように、内容ごとに構成を変える。

## 2. ページ構成

### 01 ヒーロー：一枚のビジュアルに店の気配を集約

- PCは画面幅いっぱいの生成ビジュアル。高さはヘッダーを含めて最初の画面に収まる程度を基準にする。
- 左側に文章、右側に画像を配置する構成は採用しない。
- 写真の上に、店名と短いコピーだけを重ねる。長い紹介文・料金・営業時間・複数の訴求ラベルは次の画面に送る。
- 店名は中央に配置。「カラオケ喫茶」を小さく、「チエ」を大きく組み、1つの看板として読ませる。コピーはその下に1行だけ置く。
- マイクを画面下側に置き、中央上部は暗く静かな余白にする。文字と主題が重ならない構図を採用する。
- 店名は「カラオケ喫茶チエ」。コピー候補は「歌って、笑って、ひと息。」。コピーは創作案であり店舗の既存標語ではない。
- ヘッダーには店名と小さなナビゲーション、電話導線を置く。
- スマートフォンは中央の主題が残る縦長構図。固定操作帯とブラウザUIを考慮して高さを調整する。
- ヒーロー直下に「JR小倉駅から徒歩6分」「13:00から営業」「月曜定休」を横並びの短い情報帯として配置。狭い画面では自然に折り返す。

### 02 店内：ステージと客席を異なる大きさで見せる

- `S__5783566.jpg` をステージが分かる大きな横長写真として使う。
- 短い紹介文を挟んで `S__5783567.jpg` を客席の広がりが分かる別の比率で配置する。
- 2枚を同じサイズのカードとして並べず、写真の大きさと余白に強弱をつける。
- PCではステージ写真を幅の約80%で右寄せし、その後に生成りの余白と短い紹介文を配置。客席写真は幅の約55〜60%で左寄せし、見える角度と大きさを変える。画面幅によって重なりを調整し、本文は写真の上に重ねない。
- 紹介文案：「歌う時間も、食事の時間も。小倉・京町のカラオケ喫茶チエで。」
- 「30〜40人」の情報は店内紹介の補足として掲載。正式な席数・収容人数の表現は実装時に整える。
- スマートフォンは写真と文章を縦に並べ、写真の重なりと固定スクロール演出は解除する。

### 03 食事：カレーの実写と、5品を読ませるメニュー

- `S__5783563.jpg` のカレーを大きく掲載。料理の盛り付けが残るトリミングにする。
- 続くメニューは紙のメニュー帳を思わせる罫線と余白で構成し、商品名を読みやすく並べる。
- 料理写真をセクション冒頭の中央に置き、その下で5品の名前を大きな行として読ませる。料理写真と説明文の左右二分割を反復しない。
- 掲載品：オムライス／ナポリタン／カレー／エビフライ／フライドポテト。
- 価格は未提供。管理データでは未設定として保持し、仮の金額や「時価」は表示しない。価格が分かり次第、商品名の右側へ追加する設計にする。
- 写真のない4品については料理画像を捏造せず、文字組みで魅力を出す。

### 04 利用案内：料金を理解できる組版

- 確認後の料金は、昼・夜、対象、セット内容を見比べられるHTML表として掲載する。
- `S__5783570.jpg` のチラシはこのセクションで全体を閲覧できる資料として使用。PCは補足位置、スマートフォンはHTMLの説明の後に置き、拡大表示に対応する。
- 画像の一部分だけを切り抜かず、チラシ全体を保ったプレビューを設ける。小さな画像だけに料金情報を依存させない。
- チラシには今回の営業時間・駅からの徒歩分数と異なる記載がある。現行内容が確認されるまでは「提供資料（記載内容は要確認）」として扱う。
- 「創業39周年」「音響地域NO.1」「DAM最新機種」などは、現時点の裏付けがないため本文の訴求に転記しない。
- 貸切・食事セット・飲み放題などの案内は、チラシ記載を参考情報として整理し、現行条件の確認後に掲載内容を確定する。

### 05 アクセス：実際の入口を見せて来店を助ける

- `S__5783565.jpg` の外観写真を大きく使用。紫の看板と入口が両方分かる比率を優先する。
- 住所・徒歩分数・曜日別の営業時間・定休日・電話をまとまった情報欄にする。
- 「Googleマップで見る」は住所を使った地図検索へリンクする。未確認の施設IDや評価は使わない。
- Instagramは独立したSNS行にリンクする。投稿内容を未確認のまま埋め込みや転載を行わない。

### 06 最後の電話導線

- 深いプラムの背景に「ご予約・お問い合わせ」と電話番号を大きく掲載する。
- 電話番号は `tel:0935316116` で発信可能にする。
- 「空席あり」「いつでも予約可能」など、その時点の状況が不明な文言は使わない。
- スマートフォンは画面下に「電話」「地図」の操作帯を設け、フッターと本文に操作帯分の余白を確保する。

## 4. ヒーロー画像の生成計画

参考サイトは使用せず、実写から読み取れる「紫の照明・木のテーブル・柔らかな電球の光」を生成の起点にする。

方向は、木のテーブルに横たえた1本のマイクを下部に配置した寄りの構図。背景は深いプラムと控えめな紫のぼけ、マイクにはアンバーの光を当てる。中央上部は店名用の余白として残す。実際の間取り・座席・設備を描く写真にはせず、イメージビジュアルとして扱う。

## 5. GSAP・Lenisの動き

| 場所 | 計画する動き | 目安・条件 |
| --- | --- | --- |
| 初期表示 | ビジュアルの軽いズームアウトと、店名・短いコピーの順次表示 | 0.8〜1.2秒程度。操作を待たせるローダーは設けない |
| 店内写真 | 写真が下から開くようなマスク表示と、浅いパララックス | 一度だけ表示。PCの移動量は20〜40px程度を初期値とする |
| 見出し・本文 | 小さな移動とフェードで読む順序を作る | 0.5〜0.7秒程度。日本語を一文字ずつ分解しない |
| 料理メニュー | 5品が短い間隔で順番に現れる | 各行80ms程度の差。価格や商品を動かし続けない |
| リンク | 下線・色・小さな矢印の変化 | ホバーとキーボードフォーカス双方に対応 |
| ページ全体 | Lenisの穏やかなホイールスクロール | GSAPのtickerに同期し、二重のアニメーションループを避ける |

ScrollTriggerで表示位置とアニメーションを連携させる。Lenisは公式のGSAP連携例に沿って接続する。

- スマートフォンのタッチ操作はブラウザ本来の感触を優先する。PC向けのパララックスは縮小または解除する。
- `prefers-reduced-motion` ではLenisの補間と移動演出を停止し、内容をそのまま表示する。
- JavaScriptが失敗しても写真・本文・電話・地図リンクを読める状態を基本にする。
- チラシの拡大表示は背景のスクロールを止め、閉じる操作・Esc・フォーカスの復帰に対応する。
- 音声の自動再生、点滅、強制的な横スクロール、長い画面固定は採用しない。

技術資料：
- GSAP ScrollTrigger：https://gsap.com/docs/v3/Plugins/ScrollTrigger/
- Lenis公式README：https://github.com/darkroomengineering/lenis

## 7. 実装と確認の順序

1. 本計画の独自構成をもとに、中央の店名・下側のマイク・余白の関係を整理する。
2. ヒーロー候補画像を生成し、実写5枚と合わせて画面全体の配色を整える。
3. 既存Astroプロジェクトでセクションごとの構成とレスポンシブを実装する。GSAP・Lenisは既存の依存関係を利用する。
4. アニメーション、電話・地図・Instagram導線、チラシの拡大表示を実装する。
5. 料理価格・現行の利用料金・資料の相違点を反映する。未確認情報は事実として追加しない。
6. PC・タブレット・スマートフォンで写真の切れ方、日本語改行、操作帯との重なり、動きを減らす設定はユーザーが確認する。
7. ビルドと主要リンクの動作もユーザーが確認する。こちらではサーバーを起動しない。今後起動が必要な場合はAGENTS.mdに従い `astro dev --background` を使い、`astro dev status`／`logs`／`stop` で管理する。

実装時はAGENTS.mdが指定するAstroのコンポーネント・スタイル・ルーティングの公式ガイドを作業内容に応じて参照する。本番URLが決まった段階でcanonical・OG・構造化データを整える。
